Section: "Pregătește-te pentru angajare"

Detailed guidance organized into 3 sub-sections:

Cum îți pregătești CV-ul? (CV writing guide):

Date de contact (name, phone, professional email, optional LinkedIn)
Studii (faculty, program, period, qualification — no primary school needed)
Experiență practică (internships, cadetship, tech activities, projects)
Voluntariat (student/community org roles)
Competențe (digital tools, technical apps, communication)
Limbi străine (especially English for maritime field)
Certificate/atestate (only held and relevant ones; driving license optional)
Tip: Don't exaggerate; employer must quickly identify your profile

Cum redactezi o scrisoare de intenție? (Cover letter guide):

If employer has own format, use it
Otherwise: Introduction (position, company, main reason of interest) → Content (link studies/practice/volunteering to job with concrete examples) → Closing (availability for interview, thank-you)
Keep professional tone, personalize for each application, don't copy CV

Cum te pregătești pentru interviu? (Interview prep guide):

Research the company, types of projects, job requirements
Be punctual; check address or online connection
Dress appropriately (business casual)
Prepare a short self-presentation with examples from studies/practice/volunteer
Practice English questions (maritime field)
Answer clearly and honestly; show willingness to learn
Prepare questions about responsibilities and next steps

CRM Internal Panel — Table View (Excel-like web app, NOT a shared Excel file):

Columns:

Nr. solicitare — Unique auto-incremental identifier (never renumbered)
Data/ora depunerii — Auto, Europe/Bucharest timezone
Nume / prenume / e-mail — Beneficiary data; click to expand
Calitate — Student UMC or Elev
Facultate / program / an — Filled for students; empty for elev
Categorie / subcategorie — Filled for students; empty for elev
Situația descrisă — View in case file
Status / responsabil — Filterable; assignable with audit trail
Răspuns / buton Trimite — Text editor + confirmation before email send
Autor răspuns / cont / dată / oră — Auto journal, non-editable by operators
Stare expediere — In progress / accepted by email provider / error (retryable)

Multi-user features: Individual authentication, roles, request filtering, search, sorting, simultaneous editing prevention (lock or warning), change history, XLSX/CSV export for authorized users.

User Roles (minimum):
Administrator — Accounts, nomenclatures, configuration
Operator — Process and respond to requests
Coordonator/Raportare — View and export (after authorization)
Database Schema (minimum tables):
Beneficiar: ID, name, firstname, email, type (Student/Elev), first registration date
Solicitare: unique ID, datetime, beneficiary, student fields if applicable, description, category/subcategory, status, responsible
Răspuns/interacțiune: ID, request ID, content sent, channel, functional sender, operator, datetime, delivery result
Jurnal audit: who, what, when — non-modifiable by operators
Anunț/comunicare: title, content, date, target audience, channel, status, proof, editor
Utilizator intern: identity, service address, role, rights, active/inactive status
Announcements Module ("Actual pentru tine"):

Each announcement has: ID, title, summary, short content, publish date, optional deadline, optional link, author/editor, status (draft/published/archived). The admin can create, edit, publish, archive announcements.

Project Indicators (FDI reporting):
Indicator	Requirement
A7 – Beneficiari	Minimum 400 unique beneficiaries (persons, not form submissions)
A7 – Interacțiuni	Minimum 30 managed interactions/month
A8 – Comunicări	Minimum 4 communications/month with register and proof
A8 – Baza de date	Updated at least monthly with journal and proof
RS5 (RG1.05)	Functional digital system + active database; demo + reception + reports
Deadline	A7/A8: 17 December 2026

Critical note: Publishing an announcement ≠ automatic A8 communication. Unique beneficiary count is administrative evidence (declared data, not verified identity).

Security Requirements:
HTTPS; CSRF protection; server-side validation; injection protection; anti-spam (rate limiting + invisible honeypot)
Individual accounts; role-based access; audit log; backup + restore policy; error monitoring
GDPR: data controller info, purposes, legal bases, recipients, retention periods, rights, DPO contact — displayed before submission and approved institutionally
Accessibility: field labels, keyboard navigation, contrast, explicit error messages, responsive sizing
Implementation Phases:
Content validation — UMC approves texts 01–07, logo, links, subtitles; designates editors
Page publishing — Developer builds main page + 5 informational pages; tests mobile/desktop
Announcements A8 — Publication module + communications register; editor access + export
Form + CRM A7 — Conditional data, 5×5 taxonomy, database, ID, email response, audit
Security + GDPR — IT + DPO validate hosting, email sending, rights, retention, privacy
Testing + training — Acceptance testing, 5–10 operator accounts, instructions, backup test
Launch + reporting — Reception protocol + verification of A7, A8, RS5 reports; ongoing monitoring
Things explicitly NOT included in scope:
Search functionality; student/staff login accounts; email confirmation; sidebars; complex filtering panels; downloadable CV/cover letter templates; live chat; file attachments in form; public comments; inter-beneficiary messaging; complex AI decision automations
